# Thermo-Agent: implementation plan

Written after reading the repo itself: `docs/STATUS.md`, `RUNBOOK.md`, `KAGGLE_CLI.md`, `DUAL_T4.md`, `API_USAGE_AND_PROGRESS.md`, `TEACHER_MODEL_CHOICES.md`, `TRAINING_DATA_PROTOCOL.md`, `dataset_cards.md`, `kaggle/` (kernels, lock, notebooks), `scripts/`, and `thermo_agent/` (teacher, agent, eval, train, synth). It also uses the source of the pinned TRL 1.18.1. Section 8 lists what could not be verified from the repo. Where a doc and the code disagree, the code was treated as the truth and the disagreement is listed in Gate 0.

## 1. Standing rules for the agent

- **Machine:** Windows 11, PowerShell, `.venv` (Python 3.12.3, `uv`), no WSL, no tmux. Long jobs run as `pwsh scripts/long.ps1 start <name> '<command>'` (job name must differ from the script name; logs in `logs/<name>.log`; check with `status`/`list`/`kill`).
- **Kaggle access is the CLI, through the local SOCKS proxy.** Every shell that touches Kaggle sets `HTTP_PROXY`/`HTTPS_PROXY=socks5h://localhost:10808` and `KAGGLE_API_TOKEN` read from `.env`, and `PYTHONIOENCODING=utf-8`. Never print the token. The Kaggle Benchmarks proxy key lasts about an hour; `thermo_agent.teacher.cli_runner` refreshes it.
- **Frontier models are used only through Kaggle Benchmarks** (`kaggle_benchmarks`, Kaggle's own quota), never vendor keys. Check quota before every batch (`python -m thermo_agent.teacher.cli_runner quota`), keep `--reserve` and `--max-spend` set, run a pilot before a full pass.
- **Workers never compile kernels and never receive a token.** Fused kernels come only from `kaggle/environment.lock.json`. No HF token goes into any notebook, bundle or dataset; `hf_sync` writes only to `Reza-Nadimi/thermo-agent-checkpoints`, private.
- **Repo hygiene:** no stray files, labels or notes in project files. Existing figures (SVG + PDF twin, no raster) are not redesigned; only their data files are refreshed. Paper prose is not rewritten now.
- **Living record (every gate).** Append every decision to `docs/DECISIONS.md` (new, append-only: date, gate, decision, alternatives, reason, numbers, commit). Update `docs/STATUS.md` at every gate exit. Fix any doc that contradicts the code in the same commit. Regenerate dataset statistics (`scripts/dataset_stats.py`, new) into each manifest and copy the tables into the docs: rows per task, per split, per difficulty tier (easy = `data/processed` MIX family; medium = `data/processed_arch` 65-diagram catalog; hard = `data/processed_big` 19-component cycle), per topology, per fault type, plus for trace sets accepted/attempted per model and task, cost, turns, tool calls and token histogram. Regenerate `paper/assets/*.json` with `paper/tools/generate_paper_assets.py` and run `paper/tools/verify_paper.py`; sentences the results contradict go in `STATUS.md` under "paper text to revise". One commit per gate.

## 2. What exists now (do not rebuild)

**Data pipeline (CPU, deterministic).** `scripts/gen_data.ps1` (env-driven sizes `THERMO_N_*`, `THERMO_VARIANTS=20`, resumable per step), `scripts/build_corpus.ps1` (stage, token-audit with the real Qwen3.5 tokenizer, verify, swap), `thermo_agent/synth/verify.py`. Four tasks: repair, design, audit, ledger. Ground-truth completions are programmatic expert answers with number-grounded text (`<diagnosis>`+`<edits>`, `<analysis>/<ranking>/<change>/<prediction>`, `<diagnosis>`+`<fix>`, `<rationale>`+`<design>`). These are the existing deterministic traces. Repair has 20 truthful paraphrases per ground-truth row. Current corpora: `data/sft_all` (119,807 train rows: repair 100,036, ledger 5,165, audit 2,564, design 1,894 for the original `data/sft` mix; 1,140 big-cycle rows) and `data/grpo_all` (15,022 train rows), both gated at 8,000 prompt tokens under `max_length` 8,192. Harness text (AGENTS.md + skills) is injected on 35% of rows; audit trains with skills only because agents+skills does not fit.

**Hindsight memory.** `thermo_agent/teacher/memory.py`, 342 notes (318 from rejected frontier answers, 24 from `adversarial_candidates`), `data/memory/*.jsonl`, `failure_reasons.json`.

**Teacher / frontier path.** Local driver `thermo_agent/teacher/cli_runner.py` (actions `probe`, `run`, `quota`, `sync`; journals every attempt with token cost; mirrors progress to the private HF repo). Hosted task `thermo-teacher-big-s00` v3 (`kaggle/teacher_big_task_s00.py`, zero-shot, reasoning low, 1,536 output tokens, cost cap $1.6) driven by `scripts/run_big_teacher_v2.ps1` (`kaggle benchmarks tasks run/status/download`). Tool-harness driver `scripts/kaggle_harness_cli.py` (LangGraph + toolkit + compact memory; flags `--limit --model --rounds --k-memory --reserve --max-seconds --export-dir --split --out`). Prompt exports: `thermo_agent.teacher.transfer export`, `scripts/make_eval_export.py`, `scripts/make_teacher_big_shards.py`. Spend so far $2.56 to $2.75. Measured yield: Gemini 3.1 flash-lite 513/1,600 accepted (32.1%), GPT-5.4-nano 122/1,600 (7.6%), Gemini 3.8 flash 33/200; audit has zero accepted frontier rows; the tool-harness v2 arm cost about $0.0017 per answer (120 answers, $0.2027). Provenance: `scripts/build_provenance_ledger.py` (38,202 traces, auto-discovers journals in `data/teacher_runs/`).

**Kaggle assets (all private).** Datasets: `rezanadimi/thermo-agent-code` (`scripts/make_kaggle_bundle.ps1`), `thermo-agent-corpus` (`scripts/upload_corpus_dataset.ps1`: sft, grpo, sft_all, grpo_all, heldout zips; `heldout.zip` always rebuilt), `thermo-teacher-prompts`, `thermo-teacher-prompts-big`, `thermo-agent-resume` (LoRA resume state, `scripts/resume_kaggle_checkpoint.ps1`), `thermo-agent-eval-replays`. Kernels: `thermo-kernel-wheels` (builds `causal-conv1d 1.7.0` cp313 and `fla-core`/`flash-linear-attention 0.6.0` once; its output is attached to the other kernels through `kernel_sources`, not as a dataset), `thermo-train-run`, `thermo-train-smoke`, `thermo-eval-run`. All kernels use `enable_internet: true`, GPU selected at push (`--accelerator NvidiaTeslaT4`). Pinned worker stack in `kaggle/environment.lock.json` (Python 3.13.16, torch 2.11.0+cu130, transformers 5.23.0, trl 1.18.1, peft 0.21.3, accelerate 1.16.0, datasets 5.2.0). `thermo_agent/kaggle_notebook.py::setup()` installs the wheels with `--no-deps`, fails loudly on a mismatch, and forces a consistent numpy/scipy pair (Kaggle's preinstalled numpy 2.4.4 is corrupt). HF Secrets are unreachable inside the training worker, so cross-session resume goes through the resume dataset.

**Training.** `thermo_agent/train/` (chunked cross-entropy `chunked_loss.py` + `ChunkedSFTTrainerMixin`, DDP fp16 LoRA, `hf_sync`, `merge`, `grpo.py`, `rewards.py`, `reward_diagnostics.py`), `kaggle/train_runner.py` -> `train.ipynb`, `scripts/train_dual_t4.sh`. Smoke kernel v17 trained (loss 1.59 -> 0.61 in 20 steps, about 50 s/step on one rank with reference kernels) and failed in the step-20 eval forward (OOM in the reference linear-attention `solve_triangular`). v18 with the eval-path fix and fused kernels is the current gate for the full run; its result is not in the repo.

**Evaluation.** `thermo_agent/eval/model_eval.py` (backends hf / openai-compatible / replay; `--harness none|agents|skills|agents+skills`; multi-turn Repair via `agent/loop.py::repair_loop` with verifier feedback; Design via `design_loop`/`design_refine --refine-turns`), `eval/comparison.py`, `eval/compare.py` (McNemar / permutation + Holm), `eval/tool_usage.py`, `scripts/run_replay_evals.ps1`, `kaggle/eval_runner.py` -> `eval.ipynb`. Non-model baselines in `reports/baseline_*.txt`.

**Held-out set.** `data/heldout` (seed 987654), `tests/test_cohort_coverage.py`. Test cells are tiny (4 to 16 rows).

**Paper tooling.** `paper/` with `\val{...}` slots, `generate_paper_assets.py`, `verify_paper.py`, `build_q1_evidence.py`, `Q1_CHECKLIST.md`. Three figures (`fig_audit_first_vs_second_law`, `fig_training`, `fig_corpus`) were drawn outside the repo and are stale; leave them for the later figure pass.

## 3. Decisions fixed by Reza (do not reopen)

1. The harness is an interactive multi-turn session: propose, call tools, read numeric results, revise, answer. Tools, skills, rules and failure/success memory (RAG) are exposed.
2. Every baseline model is scored twice on the same rows: **Z** (zero-shot: single turn, no tools, no skills, no memory, no rules text, all four cohorts) and **H** (the harness). 6. The agent designs the held-out set: all four cohorts, easy/medium/hard tiers, hard cycles and plants.
7. Figures are SVG and are redesigned later by Claude; paper text is updated after the project is done.

## 5. Gates

### Gate 1: regenerate data, build dev and held-out sets, rebuild corpora

1. Regenerate all ground truth with the fixed split labels: `pwsh scripts/gen_data.ps1` (set `THERMO_N_*`; design costs about 26 CPU-s per site, so about 2 h at 4,000 sites with 60 evaluations on this 16-core machine, and the step writes its split files only at the end, so do not let the machine sleep). Also regenerate `data/processed_arch` and `data/processed_big` (seeds 100/101), then `pwsh scripts/build_corpus.ps1` and `python -m thermo_agent.synth.verify` on both corpora. `data/frontier_export` stays valid (prompts unchanged).
2. **Dev set** (fresh seed, for tuning prompts, tool output format and rewards) and **held-out set** (seed 987654 or a new frozen seed, test splits only), generated with the same generators (`build_repair_data`, `audit.data`, `ledger.data`, `design.data --max-evals 60`). Design OOD splits are distribution tails (IT load >= 45 MW, ambient >= 305 K, chilled fraction >= 0.85): oversample sites and read the per-split yield from `meta_design.json` until every reported cell reaches its target.
3. Held-out design (record every count in `DECISIONS.md`): all four cohorts; every OOD split the generators support; tiers easy (MIX family), medium (65-diagram catalog), hard (19-component/34-stream steam-reheat cycle and other expert-scale plants where the generators support them; today `processed_big` covers repair and audit only, so state that for ledger and design). Target about 85 paired rows per reported cell (about 80% power for a 15-point difference); merge cells and say so where the generator cannot reach it. Current cells have 4 to 16 rows.
4. Write manifests (seed, generator commit, hash, per-cell counts, power calculation) and the full task x split x tier x topology x fault cross-table; update `data/heldout/HELD_OUT_README.md`, `docs/dataset_cards.md`, `docs/EVAL_PROTOCOL.md` (new, then frozen). Run the contamination test against every training directory.
5. Export prompts without answers: `python scripts/make_eval_export.py --dirs data/heldout --out data/frontier_heldout_export --limit <large>` (and the same for dev). Keep the training export (`data/frontier_export`) separate; ids must never overlap.
6. Upload: `pwsh scripts/upload_corpus_dataset.ps1` (rebuilds `heldout.zip`), `pwsh -File scripts/make_kaggle_bundle.ps1` then `kaggle datasets version` for `thermo-agent-code`, new version of `thermo-teacher-prompts` and `thermo-agent-eval-replays` as needed.

### Gate 2: tools and one shared multi-turn environment

- One environment class (for example `thermo_agent/agent/env.py`) holds the row, exposes the physics tools as methods with type hints and Google-style docstrings (TRL's requirement for tools), has `reset()`, and keeps the episode state. It is used by three drivers: TRL GRPO (`environment_factory`), the frontier harness (kbench tool list), and the local/HF/OpenAI-compatible generator used for Qwen and other-LLM evals (a loop on top of `agent/loop.py` and `train/prompts.feedback_message`).
- Tools (after P0-4..8): `inspect_plant`, `first_law_check`, `second_law_check`, `validity_check`, `solve_plant`. Cap output size (a 34-stream cycle's state table is long): the 8,000-token row gate must still hold with tool results included.
- Update `thermo_agent/agent/AGENTS.md` and the skills so the H prompt actually tells the model about the tools, the turn limit and the final-answer format (today the harness text contains no tool instructions). Keep the D10 inventory-then-examine guidance and D11 compact memory (what failed, what worked; no model ids, times, cost).
- Student tool-call format is Qwen3.5's native chat-template tool format. Verify with the real tokenizer that the template renders `user -> assistant(tool_calls) -> tool -> assistant` and that TRL's `supports_tool_calling` is true; record the prompt tail the way RUNBOOK section 5 did.
- Limits are configuration (max turns, tokens per turn, tool calls), identical for every H arm. Log every turn as structured data.

### Gate 3: trace generation

**3a. Deterministic tool-using traces (new, built on the existing ground truth).** The ground-truth `completion` columns stay untouched. Add `thermo_agent/synth/tool_traces.py` that turns each ground-truth row into a multi-turn trace with real tool calls and verbatim tool results:
- direct: `inspect_plant` on the broken plant -> tool result -> correct edits checked with `validity_check` -> final answer (the existing completion);
- recover: a wrong candidate from `teacher/validate.adversarial_candidates` (`no_edits`, `echo_broken`, `wrong_scale`, `third_fluid`, `bad_port`) -> tool exposes the failure -> correct edits -> pass -> final answer;
- analogous traces for audit (rank, propose, re-solve the change, confirm fuel effect), ledger (inspect lines, closure and negative-destruction symptoms, fix) and design (candidate spec -> `validity_check`/`solve_plant` -> final spec).
Reasoning text is templated from solver facts, never invented. Every trace is re-run through the verifiers: 100% accepted. Sizes are chosen from the measured SFT cost (Gate 5), not from the 100k repair rows: pick one trace variant per ground-truth plant first, and keep per-task and per-tier balance. Statistics go into the manifest.

**3b. Frontier traces through Kaggle Benchmarks.** Order matters:
1. `python -m thermo_agent.teacher.cli_runner quota`, then `probe` on the three models; stop if any returns no content or a 400.
2. Pilot with `python scripts/kaggle_harness_cli.py --model <model> --limit 20 --rounds <N>` per task (the script takes the task from each export row, so build a small pilot export per task, or run with `--limit` over a shuffled export) on `data/frontier_export` (train prompts, no answers). Record acceptance, tool calls, tokens, cost per accepted trace, truncation. Gate: acceptance above about 25% per task, otherwise fix prompts and tools first. Audit has had zero accepted frontier rows, so fix P0-5 first and pilot audit separately.
3. Full pass with the best one or two models: `pwsh scripts/long.ps1 start harness-gemini '& python scripts/kaggle_harness_cli.py --model gemini-3.5-flash-lite --limit 400 --reserve 0.5'` (journal `data/teacher_runs/harness_completions.jsonl`, progress mirrored every 25 rows to `teacher/harness_progress.jsonl` in the HF repo; resumable by id). Keep reasoning on and capture it; raise the output budget or measure truncation first (1,536 tokens with reasoning is a known risk, and format failures are already 68% on Gemini).
4. Ingest: `python -m thermo_agent.teacher.transfer ingest data/frontier_export <journal> data/frontier --memory-dir data/memory --model <slug>` (after P0-1 the row keeps the tool trajectory). Rejected rows refresh the failure memory (`data/memory/frontier_notes.jsonl`, `failure_reasons.json`); add success patterns from accepted rows to the memory so it holds what worked as well as what failed. `python scripts/build_provenance_ledger.py` picks the new journals up automatically.
5. Revisit `claude-sonnet-5-5` only for tasks where the cheap models yield too few accepted traces, and tell Reza first (standing reminder). Record yield, cost per accepted trace and failure reasons by model and task in `TEACHER_MODEL_CHOICES.md`.

**3c. Frontier zero-shot (Z) on the held-out export.** Zero-shot and harness runs share the same held-out ids. Z: `kaggle benchmarks tasks run thermo-teacher-big-s00 -m <model> --wait` against a held-out prompt dataset, or `python -m thermo_agent.teacher.cli_runner run --model <id> --split test_id ... --export-dir data/frontier_heldout_export`. H: the same `kaggle_harness_cli.py` with `--export-dir data/frontier_heldout_export --split <test split>`. Z must use the plain prompt only (no AGENTS.md, skills, memory or tool text).

### Gate 4: corpora for the tool-using student

- Build new directories (`data/sft_tools`, `data/grpo_tools`) with a new `combine`-style step; leave `data/sft_all` and `data/grpo_all` intact. Mix: deterministic tool traces + accepted frontier tool traces + (optionally) the existing single-turn rows as a documented ablation source. Report the mix per source, task and tier.
- **SFT loss masking.** `completion_only_loss=True` in `train/sft.py` masks only the prompt, so tool-result tokens inside the completion would be trained on. Implement masking for tool-result spans in `ChunkedSFTTrainerMixin` (labels = -100 on tool messages and the tool-result wrapper), normalise by the number of unmasked tokens over the whole batch, and test it.
- Decide, with the numbers, whether hidden reasoning goes into SFT targets. The student runs with `enable_thinking=False` and a short budget; the default is to train on visible diagnosis/tool-call/answer text and keep captured reasoning as a separate field for analysis. Record the decision.
- Re-run `python -m thermo_agent.train.token_audit` and `synth.verify` with tool messages rendered by the real chat template; rows over 8,000 tokens are dropped and counted, never truncated.
- Chunked loss (`train/chunked_loss.py`, already used in smoke v17) must satisfy: no (tokens x vocab) logits tensor, chunk projection plus fp32 cross-entropy wrapped in `torch.utils.checkpoint`, `ignore_index` respected, equal chunk counts on every DDP rank. Tests: loss and gradients match full cross-entropy within 1e-4 for several chunk sizes including non-divisors; all-masked chunk gives zero and no NaN; peak CUDA memory at 8K tokens recorded in `docs/DUAL_T4.md`.
- Upload the new corpora (extend the list in `scripts/upload_corpus_dataset.ps1`) and the new code bundle.

### Gate 8: multi-turn GRPO

TRL 1.18.1 (pinned) supports this natively; verified in its source: `GRPOTrainer(tools=..., environment_factory=..., rollout_func=...)`, `GRPOConfig.max_tool_calling_iterations`, a `tool_mask` that excludes tool-result tokens from the loss, an optional environment `get_reward`, and a requirement for transformers >= 5.2 (pinned 5.23.0) and a tool-calling chat template. `max_completion_length` bounds the whole multi-turn completion, so the current 320 must grow to cover turns plus tool results. `environment_factory` and `rollout_func` are marked experimental.

## 7. Risks to watch (from the repo's own numbers)

- Quota and time: one 119k-row SFT epoch was estimated at about 30 h on two T4s, before tool traces and a multi-turn GRPO sweep. Size the tool corpus from the Gate 5 measurement.

- Multi-turn GRPO sequence length and HF-generate speed on T4s; TRL's environment path is experimental.
- Qwen3.5-9B needs two T4s or 4-bit; 4B and 9B must be compared at stated precisions.
- Held-out size: cells below about 85 paired rows cannot support the paper's pairwise claims.
